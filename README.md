# ET APK 工坊 v1.0

**ET 出品 · 版权所有 © ET**

一款运行在 Android 手机上的 APK 反编译 / 修改 / 一键编译打包工具，内置可自定义的 AI 助手。

---

## 一、这是什么

| 功能 | 说明 |
|---|---|
| 反编译 | 选择任意 APK，自动在工程目录创建 `smali/`、`smali_classes2/`… 源码工程，同时保留原始资源（`apk_src/`） |
| 浏览修改 | 内置 smali 文件浏览器 + 代码编辑器，可查看/修改/重命名/删除源码 |
| 一键编译打包 | 把修改后的 smali 汇编回 dex → 重建 APK（保留原资源）→ 自动 v1+v2 签名，可直接安装 |
| AI 助手 | 设置中配置任意 OpenAI 兼容接口（API 地址 / Key / 模型），即可与 AI 对话，让 AI 分析并修改 smali 代码，一键应用后编译打包 |

## 二、安装

1. 安装 `ET-APK-工坊-v1.0.apk`（需要允许“安装未知来源应用”）。
2. 打开应用。

## 三、快速上手

### 1. 反编译一个 APK
- 主界面点「选择 APK 反编译」，选一个 `.apk` 文件。
- 等待反编译完成，自动进入工程页。

工程目录结构（在应用内部存储 `projects/<APK名>/` 下）：
```
projects/<APK名>/
├── original.apk         原始 APK 副本
├── apk_src/             解压出的原始资源（资源、assets、lib、AndroidManifest.xml）
├── smali/               classes.dex 反编译出的 smali 源码
├── smali_classes2/      多 dex 时的第 2 个
└── output/              编译打包产物
```

### 2. 修改代码
- 在工程页进入 `smali/` 目录，点开 `.smali` 文件即可编辑，保存后生效。
- 也可长按文件选择「用 AI 分析/修改」。

### 3. 让 AI 帮忙改
- 点「AI 助手」，先把关联文件发给 AI（点上方文件栏），或直接描述你的需求。
- AI 会给出修改后的完整代码（放在 `<<<ET_CODE>>>…<</ET_CODE>>>` 标记内）。
- 点「应用修改」即可写回文件，然后回工程页「编译打包」。

### 4. 编译打包
- 工程页点「⚙ 编译打包 APK」。
- 完成后可选择：**安装** / **分享** / **保存到下载**。
- 产物输出到 `projects/<APK名>/output/<APK名>-signed.apk`。

### 5. 配置 AI
- 设置页填写：API 地址、API Key、模型名、温度、最大 tokens。
- 支持任何 OpenAI 兼容接口（自有/第三方/本地服务）。
- 点「测试连接」验证。

## 四、重要说明

- **合法使用**：本工具仅供学习、安全研究、以及修改你自己拥有或有授权修改的应用。请勿用于破解盗版、绕过付费/授权校验、窃取他人数据等非法用途。
- **签名变化**：重打包后的 APK 会使用新的签名（ET），无法覆盖安装/升级原厂商签名的应用（签名不一致），属于正常现象。
- **兼容性**：重打包会保留原始资源与清单；若原应用有签名校验、加固（如 360/腾讯加固），反编译得到的可能不是原始 smali，请先脱壳。
- **编译成功率**：对未加固、标准 DEX 的应用，反编译-修改-编译可正常完成；极少数含特殊特性（如高版本 opcode、超 64k 方法的多 dex）的应用可能需调整设置中的 API 级别。
- **性能**：大 APK 反编译/编译较慢属正常（smali 引擎单/多线程受设备性能影响）。

## 五、常见问题

**Q：编译失败怎么办？**
把错误信息复制到 AI 助手，让 AI 帮忙定位 smali 语法问题并给出修复代码。

**Q：安装提示“签名不一致”？**
因为重打包用了新签名。卸载旧应用后再安装，或安装到全新环境。

**Q：AI 连不上？**
检查设置里的 API 地址（以 `/v1` 结尾更稳妥）、Key、模型名是否正确，网络是否可达；本地/内网服务需要正确填写 `http://IP:端口/v1` 且应用已允许明文流量。
